# Day 04 - K6 Performance Practice

Ngay: 2026-05-24

Muc tieu hom nay:

- Biet dung `ramping-arrival-rate` de tang RPS theo tung bac.
- Tim nguong request rate an toan cho checkout endpoint.
- Phan biet `429`, `5xx`, failed check va latency degradation.
- Viet bao cao capacity dua tren evidence, khong chi dua vao cam tinh.
- De xuat nguong SLA/SLO tam thoi cho endpoint dang test.

## Bai 1: Chay step-rate capacity probe

Dung script moi:

```text
scripts/checkout-step-rate-test.js
```

Chay voi checkout endpoint:

```powershell
$env:CHECKOUT_URL="https://your-checkout-url"
$env:START_RATE="1"
$env:MID_RATE="5"
$env:HIGH_RATE="10"
$env:MAX_RATE="20"
$env:STAGE_DURATION="1m"
k6 run --summary-export results/day-04-step-rate-summary.json scripts/checkout-step-rate-test.js
```

Script nay se tao them Markdown summary:

```text
results/day-04-step-rate-summary.md
```

Cau hoi can tra loi:

- Tu rate nao bat dau co `429`?
- Co xuat hien `5xx` khong?
- `p95` co tang truoc khi co loi khong?
- Endpoint fail vi latency, availability hay rate limit?

## Bai 3: Sua threshold theo muc tieu test

Trong `scripts/checkout-step-rate-test.js`, doc cac threshold:

```js
checkout_successful: ['rate>0.98']
checkout_rate_limited: ['rate<0.05']
checkout_status_5xx: ['count<1']
http_req_duration: ['p(95)<1000']
```

Giai thich:

- `checkout_successful`: endpoint phai tra 2xx gan nhu tat ca request.
- `checkout_rate_limited`: cho phep mot ty le `429` nho khi dang probe capacity.
- `checkout_status5xx`: khong chap nhan server error trong bai test nay.
- `http_req_duration`: gioi han latency p95.

Yeu cau:

- Neu muc tieu la regression, hay de `checkout_rate_limited` thanh `rate<0.01`.
- Neu muc tieu la capacity discovery, co the giu `rate<0.05` de test khong fail qua som.
- Ghi lai ly do chon threshold trong `results/day-04-capacity-report.md`.

## Bai 4: Phan tich loi request

Neu co loi, dung cac metric sau:

- `checkout_status_429`: so request bi rate limit.
- `checkout_status_5xx`: so server error.
- `http_req_failed`: ty le request K6 xem la failed.
- `checks`: ty le assertion pass.
- `http_req_duration`: latency tong.
- `checkout_duration`: latency rieng cho checkout group.

Ket luan theo mau:

```text
Root cause tam thoi:
- Neu 429 cao va 5xx = 0: endpoint bi rate limit, chua chac backend bi loi.
- Neu 5xx > 0: co rui ro availability/server error.
- Neu p95 tang nhung status van 2xx: he thong co dau hieu cham truoc khi fail.
- Neu checks fail nhung http_req_failed = 0: request van thanh cong ve network/status, nhung khong dat ky vong test.
```

## Bai 5: De xuat SLO tam thoi

Dua tren ket qua Day 02, Day 03 va Day 04, de xuat SLO tam thoi:

```md
## Proposed Temporary SLO

- Availability: ...
- Latency p95: ...
- Rate limit: ...
- Error budget: ...
- Regression load level: ...
```

Goi y:

- Khong chon rate cao nhat neu rate do da co `429`.
- Khong chi nhin p95 neu response `429` tra ve nhanh.
- Neu chua co unique checkout URL/session, can ghi ro risk nay trong bao cao.
