# Day 03 - K6 Performance Practice

Ngày: 2026-05-21

Mục tiêu hôm nay:

- Tách rõ performance test theo mục tiêu: availability, latency, rate limit và stability.
- Biết dùng `setup()` để chuẩn bị test data.
- Biết tạo custom summary bằng `handleSummary()`.
- Biết tag request để đọc metric theo từng nhóm.
- Biết đề xuất threshold phù hợp thay vì dùng một threshold cho mọi test.

## Bài 1: Tạo script multi-endpoint baseline

Tạo file:

```text
scripts/checkout-baseline-test.js
```

Yêu cầu:

- Gọi ít nhất 2 endpoint hoặc 2 path khác nhau nếu có.
- Nếu chỉ có một checkout URL, tách thành 2 group:
  - `checkout_page`
  - `checkout_revisit`
- Mỗi request phải có tag:

```js
tags: {
  page: 'checkout',
  step: 'checkout_page'
}
```

Gợi ý:

```js
group('checkout_page', () => {
  const response = http.get(checkoutUrl, {
    tags: { page: 'checkout', step: 'checkout_page' },
  });
});
```

Chạy:

```powershell
k6 run -e CHECKOUT_URL=https://your-checkout-url --summary-export results/day-03-baseline-summary.json scripts/checkout-baseline-test.js
```

Câu hỏi cần trả lời:

- Metric tổng có che giấu vấn đề của từng step không?
- Step nào có `p95` cao hơn?
- Step nào có lỗi nhiều hơn?

## Bài 2: Dùng setup() để chuẩn bị data

Tạo file:

```text
scripts/checkout-setup-example.js
```

Yêu cầu:

- Dùng `setup()` trả về object chứa:
  - `checkoutUrl`
  - `testRunId`
  - `startedAt`
- Trong `default function`, đọc data từ setup.
- `testRunId` phải được gắn vào tag hoặc header.

Gợi ý:

```js
export function setup() {
  return {
    checkoutUrl: __ENV.CHECKOUT_URL,
    testRunId: `k6-${Date.now()}`,
    startedAt: new Date().toISOString(),
  };
}

export default function (data) {
  http.get(data.checkoutUrl, {
    tags: { test_run_id: data.testRunId },
  });
}
```

Câu hỏi cần trả lời:

- `setup()` chạy mấy lần?
- Vì sao nên tạo test data ở `setup()` thay vì trong từng iteration?
- Khi nào không nên dùng chung data từ `setup()`?

## Bài 3: Tạo custom summary bằng handleSummary()

Cập nhật một script bất kỳ hoặc tạo mới:

```text
scripts/checkout-summary-test.js
```

Yêu cầu:

- Dùng `handleSummary(data)` để xuất thêm file Markdown:

```text
results/day-03-summary.md
```

- Markdown phải có:
  - tổng request
  - failed rate
  - p95
  - checks rate
  - kết luận pass/fail ngắn

Gợi ý:

```js
export function handleSummary(data) {
  return {
    'results/day-03-summary.md': renderMarkdownSummary(data),
    stdout: textSummary(data, { indent: ' ', enableColors: true }),
  };
}
```

Câu hỏi cần trả lời:

- Summary Markdown khác gì JSON summary?
- Khi nào nên dùng JSON?
- Khi nào nên dùng Markdown?

## Bài 4: Tách threshold theo mục tiêu

Tạo file:

```text
lib/checkout-thresholds.js
```

Yêu cầu định nghĩa 3 bộ threshold:

```js
export const availabilityThresholds = {};
export const latencyThresholds = {};
export const rateLimitDiscoveryThresholds = {};
```

Gợi ý:

```js
export const availabilityThresholds = {
  http_req_failed: ['rate<0.01'],
  checks: ['rate>0.99'],
};

export const latencyThresholds = {
  http_req_duration: ['p(95)<1000', 'p(99)<2000'],
};

export const rateLimitDiscoveryThresholds = {
  http_req_duration: ['p(95)<1500'],
};
```

Câu hỏi cần trả lời:

- Vì sao rate-limit discovery không nên fail ngay khi có `429`?
- Vì sao availability test phải fail khi status không phải `200`?
- Khi test latency, có nên tính cả response `429` vào latency không?
